Ferrum Sandbox

Ferrum delivers webhooks reliably: it never loses an event, retries failures, signs every message, and recovers from crashes. This sandbox lets you try all of that yourself in about five minutes. It costs you nothing and needs nothing installed.

Try it in your browser See a real run Fork and run the real thing View the repository Read the docs

How it works

Your app
→
API (saves the event safely)
→
Database
→
Queue
→
Workers (send, sign, retry)
→
The receiver

The event and its delivery jobs are saved in one database step, so an accepted event cannot be lost. Workers take jobs from a queue and record the result. If a worker dies, another one finishes its job.

What you can try

1. Signed deliverySend an event; the receiver verifies its signature.
2. RetriesMake the receiver fail; watch attempts at 5 s and 10 s.
3. Dead letter and replayLet a delivery give up, then re-send it.
4. Duplicate requestsPress send three times; one event is created.
5. Worker crashKill the worker mid-delivery; another finishes the job.
6. Private addressesWebhook URLs aimed at internal networks are refused.

What the tour prints

Real output from one run of make tour:

== 1. Send an event and receive a signed delivery
   The receiver checks the signature with the webhook's secret.
   sent event evt_a7b3a2824d7f86b24b3021a9217045b7
   receiver: [13:19:30] #1 POST /hook -> 200   id=evt_a7b3a2824d7f86b24b3021a9217045b7 (seen 1x)  signature=VALID  ts_age=0.8s
   Ferrum's own record:
   {"status":"success","attempts":[{"response_code":200,"latency_ms":3}]}

== 2. The receiver fails twice: watch the retries
   Retries wait 5 s, then 10 s (stored in the database, not in a sleeping worker). Takes about 20 s.
   receiver: [13:19:31] #1 POST /hook -> 500   id=evt_dc0065b371f55276f5f2a5b905b4f064 (seen 1x)  signature=VALID  ts_age=0.7s
   receiver: [13:19:37] #2 POST /hook -> 500   id=evt_dc0065b371f55276f5f2a5b905b4f064 (seen 2x)  signature=VALID  ts_age=0.0s
   receiver: [13:19:49] #3 POST /hook -> 200   id=evt_dc0065b371f55276f5f2a5b905b4f064 (seen 3x)  signature=VALID  ts_age=0.3s
   Same message id every time, so a receiver can ignore repeats.

== 3. The receiver stays broken: give up, then replay
   Using 1-second retry timers for this step so it takes about 20 s instead of 75 s.
   After 5 failed attempts the delivery is parked as dead_letter:
   {"status":"dead_letter","attempts":[500,500,500,500,500]}
   The receiver is fixed. Replaying:
   {"event_id":"evt_32e27ea9ed12ffe59765deb434585a1b","replayed_deliveries":1}
   status is now: success

== 4. Sending the same request three times counts once
   status codes: 202 200 200   (202 = accepted, 200 = already seen)
   same key, different body: 422   (422 = refused)
   one event, one delivery: the receiver got 1 POST

== 5. Crash the worker in the middle of a delivery
   The receiver holds the first request for 30 s, so the delivery is 'in flight'. Short recovery timers are used.
   killing the worker with kill -9
   a new worker finished it 3 s after the crash. The receiver saw two attempts: the abandoned one and the recovered one:
   receiver: [13:20:37] #1 POST /hook -> 200   id=evt_acd9f2c915e7b0e1f4379391f6e683ec (seen 1x)  signature=VALID  ts_age=0.1s
   receiver: [13:20:41] #2 POST /hook -> 200   id=evt_acd9f2c915e7b0e1f4379391f6e683ec (seen 2x)  signature=VALID  ts_age=0.2s

== 6. Webhook URLs pointing at private addresses are refused
   http://169.254.169.254/      "Webhook URL rejected: target address is not publicly routable"
   http://127.0.0.1:6379/       "Webhook URL rejected: target address is not publicly routable"
   http://10.0.0.5/             "Webhook URL rejected: target address is not publicly routable"
   http://localhost/            "Webhook URL rejected: internal hostnames are not allowed"

== 7. Rate limit
   8 quick requests: 200 200 200 200 200 429 429 429   (429 = slow down)
